# 웹 포트폴리오 용어사전

이 문서는 프로젝트에서 실제로 사용한 표현을 중심으로 정리한 학습용 용어사전입니다.

## HTML과 문서 구조

### HTML

HyperText Markup Language의 약자입니다. 제목, 문단, 이미지, 메뉴, 폼처럼 웹페이지 콘텐츠의 의미와 구조를 표현합니다.

### 태그(Tag)와 요소(Element)

`<p>`처럼 꺾쇠로 감싼 표시는 태그입니다. 시작 태그, 내용, 종료 태그를 모두 합친 `<p>내용</p>` 전체를 요소라고 합니다.

### 속성(Attribute)

`<a href="#about">`의 `href`처럼 요소에 추가 정보를 제공하는 값입니다. `id`, `class`, `src`, `alt`도 속성입니다.

### 시맨틱 태그(Semantic tag)

`header`, `nav`, `main`, `section`, `article`, `footer`처럼 콘텐츠의 의미를 이름으로 나타내는 태그입니다. 검색 엔진과 스크린 리더가 문서 구조를 이해하는 데 도움이 됩니다.

### DOM

Document Object Model의 약자입니다. 브라우저가 HTML을 JavaScript로 선택하고 변경할 수 있는 객체 트리로 변환한 결과입니다.

### `id`와 `class`

`id`는 문서 안에서 하나의 요소를 고유하게 식별합니다. `class`는 여러 요소에 같은 스타일이나 동작을 적용할 때 사용합니다.

### 앵커 링크

`href="#projects"`처럼 같은 페이지의 특정 `id` 위치로 이동하는 링크입니다.

### Hero

방문자가 처음 보는 큰 소개 영역입니다. 이름, 핵심 문장, CTA 버튼을 배치해 사이트 목적을 빠르게 전달합니다.

### CTA

Call To Action의 약자입니다. `프로젝트 보기`, `연락하기`처럼 방문자에게 다음 행동을 제안하는 버튼이나 링크입니다.

### 햄버거 메뉴(Hamburger menu)

모바일에서 메뉴 공간을 줄이기 위해 사용하는 세 줄 모양 버튼입니다. 누르면 숨겨진 내비게이션이 열리고 다시 누르면 닫힙니다. 햄버거처럼 가로선이 겹쳐 보여 붙은 이름입니다.

### 폼(Form)

이름, 이메일, 메시지처럼 사용자 입력을 모아 검증하거나 서버로 제출하는 영역입니다.

### `label`, `for`, `id`

`label`의 `for`와 입력 요소의 `id`가 같으면 둘이 연결됩니다. 라벨을 클릭해도 입력칸에 포커스가 이동하며 접근성이 좋아집니다.

### `alt`

이미지를 불러오지 못하거나 스크린 리더를 사용할 때 이미지 의미를 전달하는 대체 텍스트입니다.

### ARIA

화면만 봐서는 알기 어려운 역할과 상태를 보조 기술에 전달하는 접근성 속성 모음입니다. 이 프로젝트는 `aria-label`, `aria-expanded`, `aria-live`, `aria-invalid`를 사용합니다.

### `defer`

JavaScript를 HTML 파싱과 병렬로 내려받고 DOM 구성이 끝난 후 실행하게 하는 `script` 속성입니다.

## CSS와 화면 배치

### CSS

Cascading Style Sheets의 약자입니다. HTML 요소의 색상, 크기, 간격, 배치와 애니메이션을 담당합니다.

### 선택자(Selector)

스타일을 적용할 대상을 고르는 표현입니다. `.card`는 class, `#hero`는 id, `button:hover`는 특정 상태를 선택합니다.

### 선언·속성·값

`margin: 1rem;` 전체가 선언입니다. `margin`은 속성이고 `1rem`은 값입니다.

### 캐스케이드(Cascade)

여러 CSS 규칙이 같은 요소에 적용될 때 중요도, 구체성, 작성 순서에 따라 최종 스타일이 결정되는 원리입니다.

### 명시도(Specificity)

서로 충돌하는 선택자 중 어느 규칙이 더 구체적인지 계산하는 기준입니다. 일반적으로 id, class, 태그 순으로 영향력이 큽니다.

### 상속(Inheritance)

부모 요소의 일부 스타일이 자식 요소에 전달되는 동작입니다. `color`, `font-family`는 주로 상속되지만 `margin`은 상속되지 않습니다.

### 박스 모델(Box model)

모든 요소를 `content → padding → border → margin`의 상자로 보는 CSS 크기 계산 방식입니다.

### `margin`

요소 테두리 바깥쪽 여백입니다. 다른 요소와 거리를 벌릴 때 사용합니다. 배경색은 margin 영역에 칠해지지 않습니다.

### `padding`

콘텐츠와 테두리 사이의 안쪽 여백입니다. 버튼 안에서 글자와 테두리 사이 공간을 만드는 경우가 대표적입니다.

### `border`

padding 바깥을 감싸는 테두리입니다. 두께, 선 종류, 색상을 설정할 수 있습니다.

### `box-sizing: border-box`

지정한 width와 height 안에 padding과 border까지 포함해 크기를 계산합니다. 반응형 레이아웃의 크기 계산을 단순하게 만듭니다.

### Flexbox

한 방향으로 요소를 정렬하는 레이아웃 방식입니다. 내비게이션처럼 로고와 메뉴를 가로로 배치할 때 적합합니다.

### 주축과 교차축

Flexbox에서 항목이 흐르는 방향이 주축입니다. 주축과 수직인 방향이 교차축입니다. `justify-content`는 주축, `align-items`는 교차축 정렬을 담당합니다.

### Grid

행과 열을 동시에 다루는 2차원 레이아웃 방식입니다. 프로젝트 카드처럼 화면 너비에 따라 열 수가 바뀌는 배치에 적합합니다.

### `auto-fit`

Grid 컨테이너 안에 들어갈 수 있는 만큼 열을 자동으로 배치하고 남는 공간을 채웁니다.

### `minmax()`

Grid 열의 최소 크기와 최대 크기를 정합니다. 카드가 너무 작아지는 것을 막으면서 남은 공간을 유연하게 사용합니다.

### `gap`

Flexbox 또는 Grid 항목 사이의 간격입니다. 개별 항목에 margin을 반복하는 것보다 관리가 쉽습니다.

### 반응형 웹

모바일, 태블릿, 데스크톱 등 화면 크기에 따라 레이아웃이 자연스럽게 변하는 웹 설계입니다.

### 모바일 퍼스트

작은 화면용 기본 스타일을 먼저 작성하고 큰 화면에서 필요한 스타일을 `min-width` 미디어 쿼리로 추가하는 방식입니다.

### 브레이크포인트(Breakpoint)

레이아웃이 바뀌는 화면 너비 기준입니다. 이 프로젝트는 768px과 1024px을 사용합니다.

### 미디어 쿼리(Media query)

화면 너비나 사용자 접근성 설정 같은 조건에 따라 CSS를 선택적으로 적용하는 문법입니다.

### CSS 변수

`--color-bg`처럼 재사용할 디자인 값을 이름으로 저장합니다. `var(--color-bg)`로 읽으며 다크 모드 전환을 단순하게 만듭니다.

### 다크 모드

어두운 배경과 밝은 글자를 사용하는 테마입니다. 이 프로젝트는 HTML의 `data-theme` 값에 따라 CSS 변수 값을 바꿉니다.

### `position`

요소가 배치되는 기준을 정합니다. `relative`는 자식의 기준, `absolute`는 기준 요소 내부 위치, `fixed`는 화면에 고정하는 데 주로 사용합니다.

### `z-index`

요소가 겹칠 때 앞뒤 순서를 정합니다. 값이 큰 요소가 보통 더 앞에 보이며 position이 적용된 요소에서 주로 사용합니다.

### `transition`

색상이나 위치가 즉시 바뀌지 않고 일정 시간 동안 부드럽게 변화하도록 합니다.

### `transform`

요소를 이동·회전·확대·축소하지만 일반 문서 배치에는 직접 영향을 주지 않는 시각 변형입니다.

### 의사 클래스와 의사 요소

`:hover`는 마우스를 올린 상태 같은 조건을 나타내는 의사 클래스입니다. `::before`, `::after`는 HTML을 추가하지 않고 장식 요소를 만드는 의사 요소입니다.

### `rem`, `px`, `%`, `vw`

`px`는 고정된 CSS 픽셀, `rem`은 루트 글자 크기 기준, `%`는 부모 기준 비율, `vw`는 화면 너비 기준 단위입니다.

## JavaScript와 동작

### JavaScript

사용자 이벤트를 처리하고 DOM을 변경하며 API와 통신해 웹페이지를 동적으로 만드는 언어입니다.

### 변수와 `const`, `let`

값을 이름으로 저장하는 공간이 변수입니다. 재할당하지 않을 때 `const`, 재할당할 때 `let`을 사용합니다. 이 프로젝트는 `var`를 사용하지 않습니다.

### 배열(Array)과 객체(Object)

배열은 여러 값을 순서대로 저장합니다. 객체는 `이름: 값` 형태로 관련 데이터를 묶습니다.

### 함수와 화살표 함수

반복할 작업을 이름과 코드 블록으로 묶은 것이 함수입니다. `() => {}`는 짧고 일관되게 콜백을 작성하는 화살표 함수 문법입니다.

### 콜백(Callback)

다른 함수에 인자로 전달되어 이벤트 발생이나 비동기 작업 완료 시 나중에 실행되는 함수입니다.

### 이벤트(Event)

클릭, 입력, 제출, 스크롤처럼 브라우저에서 발생한 사건입니다.

### 이벤트 리스너

`addEventListener()`로 특정 이벤트가 발생했을 때 실행할 함수를 등록한 것입니다.

### `preventDefault()`

링크 이동이나 폼의 페이지 새로고침 제출처럼 브라우저가 원래 수행할 동작을 막습니다.

### `querySelector()`와 `querySelectorAll()`

CSS 선택자 문법으로 DOM 요소 하나 또는 여러 개를 찾는 메서드입니다.

### `classList`

DOM 요소의 CSS 클래스를 `add`, `remove`, `toggle`로 변경해 메뉴나 버튼 상태를 화면에 반영합니다.

### 상태(State)

현재 화면을 결정하는 데이터입니다. 이 프로젝트에서는 테마, 메뉴 열림 여부, API 상태, 폼 값을 `state` 객체에 모았습니다.

### 렌더링(Rendering)

상태를 바탕으로 DOM의 텍스트, 속성, 클래스, HTML 구조를 화면에 반영하는 과정입니다.

### `localStorage`

브라우저에 문자열 데이터를 저장하는 기능입니다. 새로고침하거나 다시 방문해도 다크 모드 선택을 유지합니다.

### 템플릿 리터럴

백틱으로 문자열을 만들고 `${값}`으로 JavaScript 값을 삽입하는 문법입니다. 프로젝트 카드 HTML 생성에 사용합니다.

### 구조분해 할당

객체나 배열에서 필요한 값을 이름별로 한 번에 꺼내는 문법입니다.

### `map()`

배열의 모든 항목을 변환해 같은 길이의 새 배열을 만듭니다. API 데이터를 카드용 객체나 HTML로 바꿀 때 사용합니다.

### `filter()`

조건을 만족하는 배열 항목만 모아 새 배열을 만듭니다. 언어별 프로젝트 필터링에 사용합니다.

### `forEach()`

배열의 각 항목에 같은 작업을 실행합니다. 메뉴 링크와 폼 필드에 이벤트를 연결할 때 사용합니다.

### Promise, `async`, `await`

Promise는 나중에 완료될 작업을 표현합니다. `async` 함수 안에서 `await`를 사용하면 비동기 결과를 순서대로 읽기 쉽게 기다릴 수 있습니다.

### `fetch()`

브라우저에서 HTTP 요청을 보내 API 데이터나 서비스 응답을 받는 함수입니다.

### API와 엔드포인트

API는 프로그램끼리 데이터를 주고받는 약속입니다. 엔드포인트는 요청을 보내는 구체적인 URL입니다.

### HTTP 상태 코드

서버 응답 결과를 나타내는 숫자입니다. 200번대는 성공, 400번대는 요청 문제, 500번대는 서버 문제를 의미합니다.

### `try`, `catch`, `finally`

`try`는 오류 가능 작업, `catch`는 오류 처리, `finally`는 성공 여부와 관계없는 정리 작업을 담당합니다.

### `AbortController`

진행 중인 fetch 요청을 취소할 수 있게 합니다. 이 프로젝트는 10초 타임아웃 처리에 사용합니다.

### Intersection Observer

요소가 화면 안으로 들어오는 시점을 효율적으로 감지하는 브라우저 기능입니다. 스크롤 등장 애니메이션에 사용합니다.

### `requestAnimationFrame()`

브라우저가 다음 화면을 그리기 직전에 함수를 실행합니다. 자주 발생하는 스크롤 이벤트의 DOM 변경 횟수를 줄이는 데 사용합니다.

### 이벤트 위임

여러 자식 요소에 각각 이벤트를 붙이지 않고 부모 하나에서 발생한 이벤트를 받아 실제 대상 요소를 찾는 방식입니다.

### `innerHTML`과 `textContent`

`innerHTML`은 문자열을 HTML 구조로 해석합니다. `textContent`는 일반 텍스트로 처리해 더 안전합니다. 외부 데이터를 `innerHTML`에 넣을 때는 이스케이프가 필요합니다.

### 이스케이프(Escape)

`<`, `>`, `&` 같은 문자가 HTML 코드로 실행되지 않고 글자로 표시되도록 안전한 문자 표현으로 바꾸는 처리입니다.

## 폼·네트워크·보안

### 유효성 검사(Validation)

필수값, 이메일 형식, 최소 글자 수처럼 입력 데이터가 정해진 조건을 만족하는지 확인하는 과정입니다.

### 정규표현식(Regular expression)

문자열 형식을 패턴으로 검사하는 문법입니다. 이 프로젝트에서는 이메일의 기본 형식을 확인합니다.

### 허니팟(Honeypot)

사람에게는 보이지 않지만 자동 입력 봇이 채우기 쉬운 필드입니다. 값이 채워지면 스팸으로 판단할 수 있습니다.

### FormSubmit

정적 웹사이트의 폼 데이터를 받아 지정한 이메일로 전달하는 외부 폼 백엔드입니다. 최초 사용 시 수신 이메일 인증이 필요합니다.

### SMTP

이메일을 발송하는 표준 프로토콜입니다. Gmail 비밀번호나 SMTP 자격 증명을 브라우저 코드에 넣으면 노출되므로 백엔드 없이 직접 사용하면 안 됩니다.

### Payload

HTTP 요청 본문에 담아 보내는 실제 데이터입니다. 문의 폼에서는 이름, 이메일, 메시지와 전송 설정이 payload입니다.

### CORS

다른 출처의 서버로 브라우저 요청을 보낼 수 있는지 결정하는 보안 정책입니다. 서버가 허용 응답 헤더를 보내야 요청 결과를 JavaScript가 읽을 수 있습니다.

### XSS

공격자가 입력한 스크립트가 웹페이지에서 실행되는 취약점입니다. 외부 문자열 이스케이프와 안전한 `textContent` 사용으로 위험을 줄입니다.

## Git과 배포

### 저장소(Repository)

프로젝트 파일과 변경 이력을 관리하는 Git 단위입니다. 줄여서 repo라고도 합니다.

### 커밋(Commit)

특정 시점의 변경 내용을 설명 메시지와 함께 Git 이력에 기록한 것입니다.

### 브랜치(Branch)

서로 독립적으로 작업 이력을 이어갈 수 있는 개발 흐름입니다. 이 프로젝트의 기본 브랜치는 `main`입니다.

### 원격 저장소와 `origin`

GitHub처럼 네트워크에 있는 저장소가 원격 저장소입니다. `origin`은 기본 원격 저장소에 관례적으로 붙이는 이름입니다.

### `push`

로컬 컴퓨터의 새 커밋을 GitHub 원격 저장소로 업로드하는 명령입니다.

### GitHub Pages

GitHub 저장소의 정적 HTML·CSS·JavaScript를 공개 웹사이트로 배포하는 기능입니다.

### 정적 사이트

서버에서 매 요청마다 HTML을 생성하지 않고 준비된 파일을 그대로 전달하는 사이트입니다. GitHub Pages가 대표적입니다.

### Live Server

VS Code에서 로컬 웹 서버를 실행하고 파일 변경 시 브라우저를 갱신해주는 개발 확장 기능입니다.

## 이 프로젝트의 핵심 흐름

```text
사용자 이벤트
→ state 객체의 값 변경
→ render 함수 실행
→ DOM의 클래스·속성·내용 변경
→ 사용자가 바뀐 화면 확인
```

예를 들어 다크 모드는 다음 순서로 동작합니다.

```text
테마 버튼 클릭
→ state.theme 변경
→ renderTheme() 실행
→ data-theme 및 버튼 설명 변경
→ localStorage에 사용자 선택 저장
```
